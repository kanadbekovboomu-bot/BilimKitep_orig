# 💻 Полиглот-Плейбуки: Концентрированные стандарты по стекам (22 языка и фреймворка)

Этот справочник объединяет лучшие инженерные правила из 22 языковых пакетов ECC (`rules/typescript`, `rules/react`, `rules/web`, `rules/python`, `rules/golang`, `rules/rust`, `rules/common`) в единый быстро читаемый справочник.

---

## 🟦 1. TypeScript / JavaScript / Node.js / Bun

- **Строгая типизация без компромиссов:**
  - Всегда ориентируйся на `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`.
  - Вместо `any` используй `unknown` с последующим сужением типа (`type guard` или схема `Zod`).
  - Используй **Discriminated Unions** для моделирования состояний (`{ status: 'loading' } | { status: 'success'; data: T } | { status: 'error'; error: string }`) вместо набора булевых флагов (`isLoading`, `isError`), которые могут прийти в противоречивое состояние.
  - Используй **Branded Types** для критичных идентификаторов (`type UserId = string & { readonly __brand: 'UserId' }`), чтобы не перепутать `userId` и `orderId`.
- **Иммутабельность:**
  - Используй `readonly`, `ReadonlyArray<T>`, `as const`, `.map()`, `.filter()`, `.toSorted()`, `.toSpliced()`, спреды `{ ...obj, updated: val }` вместо мутаций `.push()`, `.sort()`, `.splice()`.
- **Асинхронность и ошибки:**
  - Все внешние вызовы (`fetch`, SDK, БД) оборачивай в таймауты (`AbortSignal.timeout(ms)`) и структурированную обработку ошибок с сохранением первопричины (`new AppError('Failed to fetch order', { cause: err })`).

## ⚛️ 2. React 19+ / Next.js / Vue 3 / Современный Web UI & Design Quality

- **Архитектура компонентов и состояния:**
  - Держи компоненты сфокусированными (< 250 строк). Отделяй чистые презентационные компоненты от хуков бизнес-логики и сетевых запросов.
  - Не используй `useEffect` для вычисления производного состояния (*derived state*) или обработки пользовательских событий — вычисляй значения во время рендера, а побочные эффекты запускай в обработчиках событий.
  - Для серверного состояния используй `TanStack Query` / `SWR` / Server Components с оптимистичными обновлениями и инвалидацией кэша.
- **4 обязательных состояния каждого экрана/блока данных:**
  1. `Loading`: аккуратный скелетон (`Skeleton`), повторяющий геометрию контента (без скачков `CLS`).
  2. `Error`: понятное человеку описание проблемы + кнопка `Повторить попытку` (`Retry`).
  3. `Empty`: дружелюбная иллюстрация/иконка, объяснение «почему здесь пока пусто» и кнопка целевого действия (`CTA`).
  4. `Success`: основной контент с поддержкой пагинации/виртуализации при больших списках.
- **Современный CSS, UX и Доступность (WCAG 2.2 AA/AAA):**
  - Используй нативные `<dialog>`, Popover API, CSS Grid / Subgrid, Container Queries (`@container`), `:has()`, `:focus-visible`, `clamp()`.
  - Все интерактивные элементы обязаны быть доступны с клавиатуры (`Tab`, `Enter`, `Escape`), иметь видимый фокус и область клика/тапа **$\ge 44 \times 44\text{ px}$** на мобильных экранах.
  - Обязательная проверка верстки на брейкпоинтах: `1440px`, `1024px`, `768px`, `390px`, `375px` (нулевой горизонтальный скролл!).

## 🐍 3. Python 3.12+ / FastAPI / Django / Data & ML

- **Инструментарий и зависимости:**
  - Управляй пакетами через проектный менеджер (`uv`, `poetry` или локальный `.venv`), никогда не делай глобальный `pip install`.
  - Форматирование и линтинг: `ruff check` + `ruff format`, проверка типов: `pyright` или `mypy --strict`.
- **Стиль и модели данных:**
  - Полные аннотации типов (`type hints`) для всех аргументов и возвращаемых значений функций.
  - Для внешних контрактов и конфигураций используй **Pydantic v2** (`model_validate`, `ConfigDict(extra='forbid', frozen=True)`), для внутренних легковесных структур — `@dataclass(frozen=True, slots=True)`.
- **FastAPI & Async:**
  - Никогда не вызывай блокирующий синхронный I/O (`requests`, `time.sleep`, синхронные драйверы БД) внутри `async def` эндпоинтов — используй `httpx.AsyncClient`, `asyncio.sleep`, `AsyncSession` (SQLAlchemy 2.0).
  - Используй `lifespan` вместо устаревших `@app.on_event("startup")`.

## 🐹 4. Go (Golang) и 🦀 Rust

### Go:
- Всегда пробрасывай `ctx context.Context` первым аргументом во все I/O, сетевые и БД-функции.
- Оборачивай ошибки с контекстом через `fmt.Errorf("service.CreateUser: %w", err)` и проверяй через `errors.Is` / `errors.As`. Никогда не игнорируй ошибки через `_`.
- Каждая запущенная горутина обязана иметь понятный жизненный цикл, условие завершения и защиту от паники; проверяй конкурентный код с флагом `go test -race ./...`.

### Rust:
- В библиотечном и продакшен-коде запрещены `.unwrap()` и `.expect()` на путях, зависящих от внешних данных — используй `?`, `thiserror` (для библиотек) и `anyhow` (для приложений).
- Запускай `cargo clippy --all-targets -- -D warnings` перед каждым коммитом.

## 🐘 5. Базы данных (PostgreSQL / Prisma / Drizzle / Redis) и API Контракты

- **Единый конверт ответов API (Consistent API Envelope):**
  - Успех: `{ "success": true, "data": ..., "meta": { "page": 1, "limit": 20, "total": 145 } }`
  - Ошибка: `{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "Понятное сообщение", "details": [...] } }`
- **Надёжность работы с БД:**
  - Любая операция, изменяющая более одной таблицы (или проверяющая баланс/лимит перед списанием), обязана выполняться внутри **транзакции** с защитой от гонок (`SELECT ... FOR UPDATE` или условный атомарный `UPDATE ... WHERE`).
  - Добавляй индексы на все внешние ключи (`FOREIGN KEY`), поля фильтрации (`WHERE`) и сортировки (`ORDER BY`).
  - Запрещены запросы в цикле (`N+1 problem`) — используй `JOIN`, `include` / `with` или батч-загрузку (`WHERE id IN (...)`).
  - Все списковые эндпоинты обязаны иметь ограничение выборки (`LIMIT` / курсорная или постраничная пагинация, максимум 100 записей за запрос).
